EMU68AGA Pi3 RC6 - Preboot POST + Live USB Joypad Signal Receiver
18 October 2026. Pi3 bare-metal AGA-v1.117 integration.

Compiled ARM64 big-endian bare-metal test kernel, not yet hardware-verified.
Based on RC5; preserves USB FAT95 read/write diagnostics and gamepad recovery.
Moves existing diagnostic squares into a compact POST panel TOP RIGHT on the
Emu68 splash (the previous frf_boot_stage drew squares at TOP LEFT).

POST features:
 VIDEO: AGA splash initialised
 ROM + MEMORY: 68k ROM/mapping complete
 USB HOST: USPi has returned successfully
 USB KB / MS / GP / MSC: boot-enumerated device counts (K keyboard,
                         M mouse, GP wireless receiver, MSC USB storage)
 GP RX: interrupt HID reports received
 BAD: reports rejected (for example unexpected length/report ID)
 ERR: USB transfer errors
 HID ID/LEN: last HID packet report ID and size
 DECODE: successfully decoded reports
 RAW: first eight bytes of last HID report
 JOY1: last mapped Amiga joystick-2 directions
 FIRE: last mapped Amiga joystick-2 fire state
 EV: detected real input state CHANGES, not just repeated neutral packets
 Message line: receiver missing, receiving HID, or seeing real user input.

BOOT-TIME TEST:
 1. BACK UP the Pi3 FAT boot partition kernel8.img.
 2. Copy ONLY the kernel8.img in this package, leaving your ROM, overlays,
    config.txt, floppy.txt, SD partitions, and Amiga installations untouched.
 3. Boot with your ShanWan 2563:0576 wireless receiver already connected.
 4. Hold or repeatedly tap a D-pad direction or gamepad fire button while
    the splash/POST panel is displayed (approximately two seconds after USB
    enumeration in this configuration).
 5. Photograph the POST panel to help identify where the signals stop.
 6. After Workbench loads, run Amiga C:usbpad-info (included if needed)
    for persistent diagnostics; the POST overlay deliberately stops
    BEFORE guest display handoff, never drawing over games/Workbench.

The POST panel does NOT claim writes or gamepad playability is fixed.
For USB0 "write protected": retain the installed USB mass driver; run the
included read-only usbmass-mountinfo tool for partition/protection diagnosis.
Optional FAT95 USB0 mount definition with HighCyl=1 is included separately,
not installed automatically. Back up current mount first.
Use only disposable test storage for experimental writes.

If the squares you saw were actually Raspberry Pi firmware under-voltage or
rainbow warnings at the VERY top-right, those are not generated by Emu68
and may require firmware/power-supply diagnosis; this replaces Emu68's
own boot-stage squares (which were at top-left in source).

Recovery: restore RC5 kernel8.img. Only compiled; real hardware unverified.
